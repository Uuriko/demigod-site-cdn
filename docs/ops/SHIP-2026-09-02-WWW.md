## Coordinated release and rollback

1. Identify the current Worker source and prepare the URL/integrity correction with old and new release-pair checks. Do not reconstruct the Worker from public HTML or a stale mirror.
2. Before any approved publish, capture the current Webflow head/footer and Worker deployment version; inspect newer unpublished changes. Verify CDN asset responses against this manifest.
3. Apply the reviewed Worker correction and Webflow tags through the existing owner-controlled release process. This PR performs neither step.
4. Require Webflow publish completion, then read fresh HTML from the origin and public `www` on both intake routes. Check the actual script URL and integrity together and verify its fetched bytes. Confirm browser loading and an authorized intake submission before calling the intake fix live.
5. If verification fails, restore the captured Webflow blocks and matching Worker release mapping together, then verify the restored public bytes. See [the detailed rollback receipt](../../WEBFLOW-PIN.md#rollback); origin and edge pins differ.

No merge, direct update to main, Webflow publish, Worker deploy, DNS change, or private data change is part of PR #18 preparation.
